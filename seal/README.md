# @pixsettle/seal: Proof Before Pay (pbp.seal/1)

Seal what an AI agent saw, what was missing and what it decided, before any money moves.

- `commitment = sha256("pbp.seal/1\n" + salt_hex + "\n" + JCS(record))`, RFC 8785 canonical JSON, 32-byte random salt.
- Only `pbp1:<commitment>` goes on chain (Solana SPL Memo). Record and salt stay private; reveal both to verify.
- Strict validation with stable reason codes and JSON paths (never the value):
  tool outputs are sealed, `missing` evidence must be explicit `null` ("sealed ignorance"),
  `forbidden` actions are sealed, amounts are strings in minor units, and money moves without a person only
  if the amount is within `limits.autonomous_minor` (PixSettle uses `"0"`: the AI never moves money).
- Records with personal data (CPF, CNPJ, e-mail, phone, Pix random key) are refused: a hash on chain cannot be erased.
- Four verification states: `sealed`, `tampered` (edited, or sealed after the money moved), `pending`, `unverifiable`.

The Python package `pbp_seal` (IRIS embedded Python, Solana anchoring) is the reference; `test/vectors.json`
is generated by it and this TypeScript twin must match byte for byte (`npm test`).

Status: test only. Nothing here touches the main PixSettle flows, the demo or any real money.
